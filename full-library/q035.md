# 第35问 如何开始为一个开源项目做贡献

## 编辑摘要（新增，非原文）

本问从参与开源的意义出发，介绍代码、文档、设计、测试与社区支持等贡献形式，以及所需技能、项目选择方法、首次贡献流程和新手资源。

- 如何找到适合新手的项目？
- 第一次提交贡献要经过哪些步骤？

开源软件正在改变世界。从操作系统（如Linux）、浏览器（如Firefox）、编程语言（如Python），到日常使用的工具，许多都是来自全球开发者的协作成果。对初学者而言，首次参与开源既令人期待又充满未知：该如何开始？需要多高的技术水平？是否必须写代码？本文将以简单的方式，带你迈出贡献开源的第一步。

### 35.1 参与开源的意义


<!-- source: q035; print_pages: 127–128; pdf_pages: 145–146 -->

参与开源，能够更好地掌握软件开发方面的技能。软件是近百年发展最快的技术之一，特别是随着智能手机与平板电脑的普及，软件技术更是渗透到人们生活的各个方面。学会编程，并不意味着要去建立一个复杂的系统。其实，写个报表的计算公式或者做一个小动画，也可以是一种编程的体验。而开源社区，则是学习软件开发最好的“学校”。在开源社区里，有大量热心的程序员，他们乐于分享自己对技术的理解、心得，并通过各自的行动扩大自己的影响力，在协助别人的同时不断加深自己对技术的理解并提升实践能力。而新的社区加入者也可以在与社区互动的过程中找到自己的技术与精神导师（Mentor）。


<!-- source: q035; print_pages: 128; pdf_pages: 146–146 -->

通常，我们在求职时，总要提交自己的个人简历。而开源社区的贡献历程，则是更有说服力且更加透明可信的简历。越来越多的开发者会在简历中标注自己的GitHub/Gitee 账号，就是这样一种趋势。如果你是Apache 项目或者Linux 内核项目的贡献者，甚至是维护者，那么找到一份好工作将会更加容易。

除了以上两种比较功利的目的，还有两种不那么功利的目的。一方面是在社区里结交更多的朋友，另一方面则是通过贡献社区，创造全新的功能，获得心理上的满足感。也有很多朋友，原本是抱着功利的目的来到社区，却收获了更多的快乐与荣誉。

### 35.2 贡献的多种形式

也许有人会认为，要给开源做贡献，就必须先学会写代码。其实还有很多种贡献开源的方式，如表35-1 所示。

表35-1 贡献开源的方式

| 贡献方式 | 具体内容 |
| --- | --- |
| 修复代码 | 修复程序错误或开发新功能 |
| 完善文档 | 修正拼写、更新示例、翻译内容 |
| 设计优化 | 改进界面或设计图标 |
| 测试反馈 | 测试软件并报告问题 |
| 社区支持 | 解答问题、参与讨论、整理常见问题、组织线上或线下活动、技术布道等 |
除了编写代码，社区还需要做大量的文档编写、完善、翻译等工作。有不少开源项目代码本身写得不错，文档却一塌糊涂，如果有人能够帮助他们完善文档，他们都会非常感激。如果你还有不错的审美，能够做一些视觉设计，就更是社区最紧缺的人才，太多的开源软件，UI/UE 都亟待改进。

作为一个开源软件的普通用户，在使用过程中遇到问题，及时、准确、完整地提交缺陷报告（Bug Report）也是非常重要的社区贡献。

另外，在一个内向型人格积聚的地方，如果你正好是外向型人格，乐于分享，善于交流，喜欢组织线上线下的活动，甚至能登台演讲，那就更好了。社区的发展，离不开社区支持与运营的贡献。

总之，你不能完全不懂技术，但是也不必成为编程高手，就能够加入社区，并且为社区作出贡献。

### 35.3 需要的基本技能

虽然不需要成为编程高手，但是基本的技能还是需要掌握的。


<!-- source: q035; print_pages: 129; pdf_pages: 147–147 -->

（1）Git 版本控制。现在几乎所有的开源项目都会托管在GitHub、GitLab、Gitee 或者类似的代码托管平台上。这些平台无一例外都使用Git 来管理代码版本。所以，理解什么是版本、版本控制工具、仓库、分支与提交、Fork 与发起Pull

Request 等都是开发者必须掌握的基本功。推荐学习《Pro Git》中文版，这是一本免费的电子书，在线就能搜到。

（2）代码托管平台。GitHub、GitLab、Gitee 等平台的基本操作其实非常简单，而且这些平台的操作大同小异，只需要学一遍就行。

（3）阅读能力+耐心。开源社区都比较强调自助服务。你来到一个社区，首先应尽量阅读文档，尝试自己理解并运行相关软件，只有确实遇到困难，才去求助。而不是在社区里反复提交一些早已被回答过无数遍的问题。

（4）沟通能力。又是一个软技能，学习礼貌、清晰、有条理地提问，有理有节地回答问题，非常重要。特别需要注意：提问前先查阅文档和历史讨论记录；清晰地描述问题或改动目的，避免模糊表达；保持礼貌，尊重不同意见；理解维护者多为志愿者，耐心等待回复。无论你出于什么样的目的，仅仅是一次性的贡献，还是永久性地加入社区，都得和他人进行沟通和交往，这是你要在开源圈发展的必须修炼的技能。

### 35.4 寻找适合新手的开源项目

选择一个开源软件，首先要明确的是，自己的动力何在。是出于兴趣？还是出于工作需要？例如，有人对搜索引擎特别感兴趣，想了解它是怎么做出来的。那么可以考虑先寻找一些专业的书籍，来了解一些关键的知识点。如果对于某一领域的知识点缺乏必要的了解，可能完全无法理解一个项目里的代码。在掌握初步的知识以后，自然可以去找一些常见的开源项目来学习。也可能是出于工作需要，例如，平时使用PHP 开发Web 应用时已经在用某一个常见的PHP 框架了，希望能够对这个框架有更深入的了解，甚至希望横向地比较多个不同的PHP 框架，这些都是非常清晰的目的。这样在学习的过程中，才不会迷失方向。

比较危险的一种情况是，听说某某项目很有名气，甚至是为了将来找工作更容易，就贸然一头扎进某个项目中去了。怀有这种学习目的的人，往往会选择那种很庞大且成熟的项目，打开文件夹一看，成百上千的源文件根本无法看完，一下子就懵了，然后灰心丧气，更容易放弃。

一、优先选择能够独立运行的项目

开源的项目有很多种类，能够独立运行的项目很多。但也有不少项目是其他开源项目的插件、类库或扩展包，这些在一开始接触开源时最好不要涉猎，因为理解这些项目可能需要理解它们背后的庞然大物，这往往会遭遇很多难解的细节，一不小心就无法继续进行。

当然，还有一类项目虽然能够独立运行，但要成功运行还需要安装和配置许多其他依赖项目，这往往会让初学者特别绝望，折腾了一个星期，项目居然还不能正常运行！


<!-- source: q035; print_pages: 130; pdf_pages: 148–148 -->

因此，那些规模小、能够独立运行且不依赖于太多其他项目的开源项目，可以优先选择。

补充说明：在Docker 出现以后，运行一个项目往往只需要一行简单的命令。在Github 上，也能找到很多demo 项目，或者是docker-compose.yml 文件，这些都是很好的入手点。

二、选择活跃的项目

项目的活跃程度包括两个方面：一方面是开发者提交新代码的频繁程度，另一方面是在社区中对这个项目的讨论热烈程度。代码提交越活跃，参与的人越多，越能证明这个项目很有价值，也表明它值得你投入精力学习。而项目在社区讨论的热烈程度，则确保当你遇到问题的时候，能够搜索到别人的答案，或者你自己提问以后，能够有人热心回答你。

当然，活跃程度都是相对的，如果你真的对一个项目感兴趣，可以试着直接给这个项目的作者发邮件、提问题。大多数开发者都会很高兴有人关注他的项目，通常也会热心地回答你的问题。

三、判断代码质量

并非所有的开源项目都是高手写的，都值得你去学习。事实上，有很多低质量开源项目，仔细查看会发现其代码写得一塌糊涂。所以，试着阅读一下这个项目的代码。至于如何判断一个项目的代码质量，笔者在知乎曾回答过一个类似的问题“如何让自己写的代码易维护？”推荐给各位朋友参考。当然，更加推荐的是阅读《代码整洁之道》一书，这是一本非常好的介绍如何提高代码质量的书。

四、搜索技巧

在GitHub 上搜索标签：is:issue is:open label:"good first issue"（新手任务）或label:"help wanted"（急需帮助）。通常能够找到不少对于新手友好的任务，但是这些任务所属的项目是否适合你，还得通过前面的几条来判断。

### 35.5 第一次贡献的完整流程

以在GitHub 上为某个项目修复文档错别字为例，在动手执行下面的8 个步骤之前，还要确保你的机器上已经正确安装了Git 客户端。

（1）Fork 仓库：在该项目的主页单击“Fork”按钮，复制到你的账户。

（2）复制到本地：运行命令git clone https://github.com/你的用户名/项目名.git。

（3）创建新分支：执行git checkout -b fix-typo-readme 建立修改分支。fix-typo-readme 是你为这个分支起的名字。

（4）修改内容：用文本编辑器修正文件（如README.md）。

（5）提交更改：依次运行git add README.md 和git commit -m "修复README 中的拼写错误"。

（6）推送分支：使用git push origin fix-typo-readme 同步到远程仓库。


<!-- source: q035; print_pages: 130–131; pdf_pages: 148–149 -->

（7）发起合并请求：在GitHub 的项目主页上单击“Compare & pull request”按钮，描述修改内容。若关联已有问题，请注明“Fixes #问题编号”。


<!-- source: q035; print_pages: 131; pdf_pages: 149–149 -->

（8）响应反馈：根据维护者建议调整代码，直至合并完成。

在GitHub 上有一个著名的开源项目，能够帮助那些想要做出自己的第一次开源贡献的朋友，名字就叫first-contributions。

### 35.6 其他帮助新手入门的资源

- MunGell/awesome-for-beginners：一个包含各种编程语言和技术的初学者友好项目列表。

- First Timers Only：帮助新手参与开源项目的网站，提供指导和项目列表。

- HelloGitHub：一个专注于分享GitHub 上有趣、入门级开源项目的社区，特别适合中国用户。

- 如何选择（并贡献）第一个开源项目：GitHub 官方搜集的适合新手入门的项目。

### 35.7 开始行动

参与开源无须一步到位，一次微小的改进就能成为社区一员。与其瞻前顾后，不如轻松一跃。开源世界始终向所有愿意参与的人开放。每一次贡献都在推动技术进步，祝你的开源之旅顺利启程！
